# 工具参数契约（统一预检层）

2026-10-22 建立。解决的是同一类失败：**工具本身没坏，但调用形式不对**——
参数名按自然叫法传（`server` vs `name`）、长内容被输出上限截断导致参数为空、
必填/枚举漏传。以前每类都在各工具里各写一套文案，错误格式五花八门，模型只能猜。

## 一处拦截

所有工具调用都经过 `core/registry.py` 的 `execute()`，顺序固定：

```
execute(name, args)
  ├─ _normalize_args   别名归一（server → name、context → content…）
  ├─ _args_broken      参数不是合法 JSON（多半是长内容被截断）→ 直接返回 args_broken
  ├─ _preflight        必填缺失 → param_missing；枚举不合法 → param_enum
  └─ 分发              python_function / go_binary / mcp
```

工具函数因此可以假定「参数已经过校验」，只需专注业务逻辑。

## 错误信封（三种，格式统一）

| error_code | 何时 | 附带字段 |
|---|---|---|
| `param_missing` | schema 里 required 的参数没传 | `missing`、`received`、`retry_with`（含真实已传值 + 枚举默认值，可直接照抄） |
| `param_enum` | 枚举参数传了非法值 | `param`、`allowed`、`received`、`retry_with` |
| `args_broken` | 参数不是合法 JSON（截断/语法错） | `error` 里说明原始长度与建议 |

`retry_with` 是**机器可读的重试参数**：前端、模型、脚本都能直接拿它重发，不必解析中文文案。

## 怎么给工具加别名

在 `@tool(...)` 里加 `aliases={"别名": "正式名"}`：

```python
@tool("mcp_connect", "...", {...}, aliases={"server": "name"})
def run_connect(name: str = "", server: str = "") -> dict: ...
```

要点：

1. **别名只进注册表，不进发给模型的 schema**——schema 里多写一个名字反而干扰模型选参数。
   模型该看到的是唯一正解，别名是给"它已经叫错了"的情况兜底。
2. **证据驱动**：只在 operation.log 里真的出现过该叫法才加，不要凭想象铺别名
   （铺多了会掩盖真实错误）。
3. 函数签名可以同时保留旧名字（`server: str = ""`）做双保险，但以注册表里的 aliases 为准。

已加：

| 工具 | 别名 |
|---|---|
| mcp_connect / mcp_disconnect | `server` → `name` |
| ws_write | `context` → `content`，`file` / `filepath` → `path` |

## 护栏怎么写

结构性护栏（确认口令、破坏性命令拦截）保持"工具内检查"，但要满足两条：

1. **枚举化**：`confirm` 这类参数在 schema 里写 `enum: ["DELETE"]`，模型没得选错；
2. **给出路**：报错里必须包含可直接照抄的调用示例或替代工具名，
   只说"请确认后使用受控方式"等于把模型卡死（cmd_run 曾因此空转 36 次）。

## 怎么发现新的坏味道

```bash
python tools/scripts/tool_timing_report.py --days 7     # 失败率排行
```

失败率高的工具，拉 operation.log 里它的失败记录，按错误文案归一化聚类：

- 出现 "unexpected keyword argument 'X'" → 加别名（X → 正式名）
- 出现 "missing required positional argument" 且 args 为空 → 多半是截断，检查该工具是否鼓励一次写长内容
- 出现"护栏拦截"但文案没给替代路径 → 补替代路径
- 命令非零退出 / 超时 / 服务未启动 → 业务失败，不是契约问题，别改文案
