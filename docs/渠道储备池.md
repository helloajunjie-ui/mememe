## 二、储备源（3，均 `enabled:false`）

### 1. OPENAI-LABS ✅能用，卡在通道

| 项 | 值 |
|---|---|
| 端点 | `https://www.openai-labs.com/v1` |
| 实测 | 2026-10-14：`/v1/models` → 200（**252 个模型**）；`/v1/chat/completions` → **200，取回真实内容** |
| 障碍 | **不是充值，是通道**。本地 DNS 被 Clash TUN 劫持为 fake-ip `198.18.0.71` → 直连超时、走代理(7897) CONNECT 200 但数据卡死 |
| 破法 | 钉真 IP：`--resolve www.openai-labs.com:443:15.204.107.121` → 200 / 2.24s。真 IP 由阿里 DoH(223.5.5.5) 独立确认 |
| 真实归属 | OVH 机房，NS=腾讯 DNSPod（国内注册）→ **该站国内本可直连，是本地代理层挡的路** |
| ⚠️ 风险 | ① 模型列表 ≠ 可用（`claude-haiku-4-5` → 503 no available channels）② **存在模型替换**（请求 `deepseek-flash` → 响应 `model` 字段为 `deepseek-v4.1-flash`）③ new-api 类中转面板（报错泄露内部分组 `gcBusiness`/`OpenAIVIP`/`claude-max`/`ultimate`）→ **请求内容全部可见，禁止发送私有上下文** |
| 启用条件 | 通道打通（在我方网关侧做 DoH 自解析，**不动用户的 Clash 配置**） |
| 定位 | 容灾池 / 探索用途，不进关键路径 |

## 三、启用 SOP（照做即可）

1. 改 `config/llm.json` 对应源 `enabled: true`（改前先备份 `llm.json.bak_before_xxx`）。
2. 若有通道障碍（如 OPENAI-LABS），**先在我方网关侧解决**（自解析真 IP），不碰用户的 Clash / hosts。
3. 启用后**第一件事**是实弹验证：`chat/completions` 取回真内容，并确认响应 `model` 字段与请求一致（防模型替换）。
4. 任何涉及私有上下文（记忆/对话/项目材料）的调用，只走可信主源。

## 四、Key 存放现状

- 各源 key 目前**明文存于 `config/llm.json`**，与既有各源同处理。
- 任一储备源**准备进关键路径前**，应迁移到加密凭据库（account_add），不留在明文配置里。
