## 结论先行

评测集跑出 3 个 FAIL，但**根因不在同一层**——分层比数量重要：

| 症状（库里实测） | 根因层 | 位置 | 状态 |
|---|---|---|---|
| 内部调度消息入库 **61 条** | 喂料口未过滤 | `core/agent.py` L1921 + `core/memory_extract.py: auto_extract` | 口子**已堵**(2026-10-10) |
| 同一事实 **12 条**重复 | 写入去重太弱 | `core/memory.py: _add()` | **仍在产生** |

一句话：**去重弱是「病根」，喂料脏是「外感」，相对时间是「营养缺乏」——三样得分开治。**

## 1. 内部调度消息入库（61 条）

**证据**：`memories` 里含 `任务：（内部·` / `自主探索` 的条目 61 条
（#149/#171/#174/#179/#184/#187/#189/#194/#199/#209/#211/#237/#240/#244/#247/#250/#262/#265/#303/#323…），
多为 `type=episode` 且已 `archived=1`。内容是**半截残句**，如
`任务：（内部·自主时间）现在是你被安排的自主时间。…把有意义的收获沉淀进记忆\n结果：自主时间收尾。本次探索围绕`。

**根因**（两处叠加）：

1. `core/agent.py` L1921 调用处把 `self.history[-12:]` **整段**传进去，不区分 role：
   ```python
   [{"role": m.get("role"), "content": m.get("content")} for m in self.history[-12:]]
   ```
2. `core/memory_extract.py: auto_extract()` 内部同样**不做 role/内容过滤**，且 `content[:300]` **硬截断** ——
   这解释了残句：截断发生在切片处，结果是「一句话说一半」被存进长期记忆。

**旁证（很有说服力）**：`run_eval.py --live` 里 `internal_prompt_rejected` 是 **PASS** ——
**提炼器其实认得出那是系统消息，不会主动存**。锅确实在喂料口。

**修法**（未实施）：在 `auto_extract` 内部加一道防御性过滤，不依赖调用方自觉：
```python
_INTERNAL_MARKERS = ("任务：（内部·", "请自由探索了解世界", "自主的整点反思时间")
recent = [m for m in turns[-EXTRACT_MAX_MESSAGES:]
          if str(m.get("role") or "").lower() in ("user", "assistant")
          and not any(mk in str(m.get("content") or "") for mk in _INTERNAL_MARKERS)]
```
用**固定文案特征**而非泛词 —— 泛词会误伤（见下方判据修订史）。

## 2. 同一事实 12 条重复

**证据**：`『尼可』` 名字类短条目 12 条，措辞各异：
`用户名叫「尼可」/使用者名为「尼可」/使用者被称作「尼可」/使用者被称为"尼可"/用户常被称作「尼可」/…`

**根因**：`core/memory.py: _add()` 的去重是**精确字符串相等**：
```python
norm = " ".join(content.split())            # 只压缩空白
dup = self.conn.execute(
    "SELECT id, importance, tags FROM memories WHERE archived=0 AND scope=? AND content=?", ...)
```
`「用户名叫尼可」` 与 `「使用者名为尼可」` 只差几个字，**字符串不等 → 判为不重复 → 直接新增**。
提炼器每次措辞不同，于是每提炼一次就多一条，12 次攒成 12 条。

**认知纠正**：我此前以为 WeKnora 的 **tier2 bigram 归并**已经落地到记忆链路 ——
**读代码后否证**：`_add()` 里没有任何近似匹配。（我只核实了 `_add()` 这一段；
tier2 实现若存在于别处，也**没接到这条写入路径上**。这是「记了完成、实际没通」的典型。）

**修法**（未实施，**风险最高，需单独立项**）：`_add()` 先精确匹配，命中不了再做近似 ——
bigram Jaccard ≥ 阈值（建议 0.85）**且同 category** 才视为重复。
**不要全局开**：只在 `auto_extract` 写入路径启用，避免误合并手工写入的相近事实。

## 3. 相对时间入库（10 条）

**证据**：含「下周」3 / 「明天」3 / 「后天」1 / 「这周」1 / 「昨天」2。

**根因**：`_extract_prompt()` 的 5 条规则里**没有**时间归一化要求，
也没有把「当前时间」作为锚点注入提示词。存下「下周三」三个月后即失效且无法回收。

**修法**（未实施）：加规则 6 并注入时间锚：
```
6. 涉及相对时间（今天/明天/下周三/这周五等）必须换算成绝对日期。
   当前时间：{YYYY-MM-DD HH:MM}（星期X）。
```
建议 `_extract_prompt` 增加 `now` 参数以便评测可复现（否则 live 分数随时间漂移）。

## 4. 评测集自身的盲区（这轮最值钱的发现）

`--live` 结果 7/10，其中 **`same_fact_many_rephrasings` 是 PASS** ——
可库里明明躺着 12 条重复。

**因为单次提炼本来只会产 1-2 条。12 条是跨 12 次提炼累积出来的。**

> **单次评测天然看不见「累积型退化」。**

任何会跨次叠加的机制（记忆去重、缓存、日志、计数器）都有这个盲区：
单次行为完全正确，N 次之后才崩。

**待补**：一个「累积模式」——把同一事实以不同措辞喂 N 次，看库里**最终净增几条**。
这才是测 `_add()` 去重是否真有效的正确姿势。
