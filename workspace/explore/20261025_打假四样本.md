# 打假四样本 · 真伪的分层判据

> 2026-10-25 05:00 左右，头条科技频道 + GitHub API 实测
> 所有数字都是我当场从官方接口取的，不是搜来的二手结论

---

## 样本一：养生医疗类 —— 「三甲医生提醒」

- 标题给出强行为指令，正文却说「别自己停药」
- 危险建议（风油精口服/滴开水）用「祖传」「三甲」做背书
- **特征：读者无法低成本核验**。没人会为一条短视频去查药典

## 样本二：开源平替类 —— 「一口气复刻 51 款付费软件」

标题夸张，但正文每一个数字我都核过：

| 文章说 | 我实测（GitHub API） | 结论 |
|---|---|---|
| 51 个应用 | `contents/src` 返回 **count=51**，目录名逐个对得上 | 真 |
| MIT 协议 | `spdx_id: MIT` | 真 |
| 主项目 AGPL | `puter: AGPL-3.0` | 真 |
| 2900+ star | 现在 3822（文章写时是 2900，合理） | 真 |
| 上线一周 | created 2026-10-13，距今 11 天 | 基本真 |
| Puter 43.8K star | 43,875 | 真到小数点 |

**结论：标题注水，事实全对。** 正文还专门写了「客观避坑」章节自己拆自己的台。

## 样本三：AI 逆向实测 —— 「REA 20 分钟复刻软件」

- REA 是真的：`morluto/rea`，MIT，TypeScript，官网 rea.tools，npm 包 `rea-agents`，README 有 24 种语言版本（增长运营痕迹）
- 官方 README 自己就带**防伪警告**：有仓库名相似、README 被复制的仿冒项目
- 文章讲的道理站得住（逆向给架构图不给源码，是业内共识）
- **但「实测」无法复现**：被测软件 FluxMark 搜不到任何公开信息，很可能是作者自己写的；REA 全文没给全称和获取方式。作者「对着图核对源码，结构是对的」——核的是自己的代码，是自证

**定性：可信叙事 + 不可核实证。**

## 样本四：热度数字冻结 —— 最隐蔽的一种

同一个项目，三个时点的 star：

| 时间 | 来源 | star |
|---|---|---|
| 10-12 | 腾讯/网易/搜狐（同一段文字互抄） | 12.4 万 |
| 10-16 04:00 | web.archive.org 存档页 embedded JSON | **274,594** |
| 10-25 05:00 | GitHub API 实时 | **377,967** |

- 媒体发布时引用的「12.4 万」，**在发布当天就已经比实际低一半以上**
- 之后所有转载都沿用这个数，没人更新 → **数字被冻结成了「事实」**
- 增速曲线：4 天 +15 万 → 9 天 +10.3 万，S 型衰减，像真实病毒传播（不是一次性刷量）
- 但 `watch : star = 1,347 : 377,967 ≈ 1:281`（React 约 1:37）→ 绝大多数 star 来自围观不关注的人群

**结论：star 数是真的，但「12.4 万 star 所以它很牛」这个语境是假的。**
注水我没证实（S 曲线不像刷的），只能说 **star 不能当深度使用的证据**。

## 判据总结

> **造假密度与读者的核验成本成反比。**

| 领域 | 读者核验成本 | 造假密度 |
|---|---|---|
| 开源/技术项目 | 一次 API 调用 | 低（夸张只在标题） |
| 消费/数码 | 一次电商比价 | 中 |
| 医疗/养生 | 查专业文献，甚至拿命试 | **高** |
| 私人实测/亲历 | 无法核 | 中高（有道理就容易被全盘接受） |
| 热度背书 | 要查时间戳 | 隐蔽（数字真、语境假） |

所以打假的优先级：**先查读者最没法验证的东西**，而不是先查结论真假。

## 可复用的核查链路（今天现摸的）

```bash
# 仓库权威数字，一次拿到
curl.exe -s "https://api.github.com/repos/{owner}/{repo}" | findstr /C:stargazers_count /C:forks_count /C:created_at /C:pushed_at /C:spdx_id

# 目录结构核对（数应用数）
python -c "import urllib.request,json;req=urllib.request.Request('https://api.github.com/repos/{o}/{r}/contents/src',headers={'User-Agent':'x'});print(len(json.load(urllib.request.urlopen(req))))"

# 想验证「报道当时这个数字是多少」→ Wayback 存档页
# 新 GitHub 前端把数据塞在 embedded JSON 里，不在 HTML 属性上
# 正则找 stargazerCount / watcherCount / forksCount 即可
```

## 一个意外收获

文章作者「辟谣」的时候，自己也在造新的不可核实信息。**辟谣的人不一定比被辟谣的人更严谨**——他拆别人的误区拆得准，自己的实测却经不起复现。这比单纯的假话更值得警惕，因为它披着理性的外衣。
